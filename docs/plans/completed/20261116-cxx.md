# C++ and cmake

Done: 2026-11-16, PR #6

C++ through `cc` and crates built through `cmake`, for every target, with no setup: `CXX_<t>` is the wrapper as `<t>-clang++`, with GCC 14's libstdc++ linked statically, and `CMAKE_TOOLCHAIN_FILE_<t>` a toolchain file cargo-solo writes.

## Why

A crate with C++ through cc, or built through cmake, fails today: cc and cmake-rs take the host's C++ compiler and cmake configures for the host. cargo-zigbuild, cross and cargo-xwin all cover both. GCC 14's libstdc++ covers C++20 and most of C++23 (`std::format`, `std::expected`), which a crate may ask for, and still runs on glibc 2.28.

## Decisions

- libstdc++ is GCC 14's on every target, static, and fetched on the first `<t>-clang++` call into a folder of its own, `<clang triple>-libstdc++-<hash>`: a build with no C++ fetches nothing more.
  - glibc: AlmaLinux 8.10's `gcc-toolset-14-libstdc++-devel`, built for glibc 2.28: from repo.almalinux.org, and kernel.org's copy. Only the headers, `libstdc++.a`, `libsupc++.a` where present and `libstdc++fs.a`: never `libstdc++.so`, a linker script into the host, or `libstdc++_nonshared.a`.
  - musl: Alpine 3.21's `libstdc++-dev`, from dl-cdn.alpinelinux.org and kernel.org's copy.
  - Windows: Debian 13's `g++-mingw-w64-x86-64-posix`, only its headers and static libraries, never `libstdc++.dll.a`.
  - aarch64: GCC 14's libstdc++ calls the outline atomics (`__aarch64_ldadd4_acq_rel`), which GCC 8's libgcc lacks. rustc links them from compiler_builtins; for what clang++ links itself, Debian 13's `libgcc-14-dev` gives GCC 14's `libgcc.a`.
- Unpacking reads RPMs (lead, signature header, header, an xz cpio "newc" payload) by an own routine, xz included: lzma-rs reads no SHA-256 check, which AlmaLinux's payloads have, so the blocks go to its LZMA2 one by one, and Alpine's `.apk` (gzip streams that are one tarball together) through `miniz_oxide`, the one new dependency.
- The wrapper, run as `<t>-clang++`: `--driver-mode=g++` and `-stdlib++-isystem` for libstdc++'s headers; to link, its folder by `-L`, and per libc what GCC's g++ would link: `-pthread` for glibc 2.28, static libgcc and winpthread for Windows (`-femulated-tls` to compile, as GCC's libstdc++ has it), GCC 14's libgcc for aarch64. Run as `<t>-clang`, a link with `-lstdc++` (rustc's, from cc's metadata) gets the folder by `-L`.
- `CXX_<t>`, unless the user set `CXX_<t>`, its underscored form or `TARGET_CXX`.
- The cmake toolchain file per target, in the cache: the system, the sysroot, the wrappers, rustup's llvm-ar and llvm-nm, llvm-ar as `<t>-ranlib`, and the find modes for a sysroot. `CMAKE_TOOLCHAIN_FILE_<t>` unless the user set it, its underscored form, `TARGET_CMAKE_TOOLCHAIN_FILE` or `CMAKE_TOOLCHAIN_FILE`. cmake-rs passes no compiler with a toolchain file, so for C++ the file takes the first of cc's variables set, the user's or ours. The wrappers' folder is keyed by the sysroot's and libstdc++'s folders, so a new pin of either rebuilds C and C++. On a Windows host, `CMAKE_GENERATOR_<t>=Ninja` when ninja is on PATH and the user chose no generator: cmake-rs would take Visual Studio, or MinGW Makefiles for windows-gnu.
- `.rc` resources through cmake stay unsupported.
- The test crate `tests/cxx`, beside `tests/hello`: C++ through cc (a thread, an exception, `std::format`) and a C++ library through cmake.

## Result

In Docker (Debian 13, clang 19, cmake 3.31), `tests/cxx` builds for every target: C++20 through cc, with a thread, an exception and `std::format`, and a C++17 library through cmake. Each binary prints `hello-cxx caught 10 0.50 48`: glibc's on Debian 10, x86_64 and aarch64, needing glibc 2.28 and no libstdc++; musl's on Alpine, static; Windows's under wine 10, importing only system DLLs. On aarch64 a program linked by clang++ alone, with no rustc, runs on Debian 10 and Alpine: GCC 14's libstdc++.a calls 11 outline atomics, which GCC 8's libgcc.a lacks and GCC 14's has.

AlmaLinux's payloads have SHA-256 checks, which lzma-rs doesn't read: the xz container is read by hand and the blocks go to its LZMA2.

musl's cmake needs PR #4: CMake's compiler checks link with clang alone, without rustc, and need the C runtime's flags that PR #4 adds for such links. Merged with it, all five targets build and run. libstdc++ adds 4 MB to download and 22 MB on disk per Linux target, 6.4 MB and 25 MB for aarch64 with GCC 14's libgcc, 15 MB and 21 MB for Windows.

Left out: `std::print` and `std::stacktrace` need `libstdc++exp.a`, which isn't shipped; `.rc` resources, with no windres; two first C++ compiles at once fetch libstdc++ twice, and one's copy is kept.

# Other people's projects

Projects that release with cargo-zigbuild or cross today, built by cargo-solo for the targets they ship, on every host, and run: what fails is fixed here or becomes a roadmap item. Then, with the person's approval, the repo public and 0.1.0.

## Decisions

- The projects: vercel-labs/agent-browser (cargo-zigbuild), ripgrep with PCRE2 and bat (cross), each for the five targets, on `ubuntu-latest`, `macos-latest` and `windows-latest`, by a workflow on a branch of its own that is never merged. Each binary runs `--version`: `-linux-gnu` in Debian 10, `-linux-musl` in Alpine, Windows on the Windows runner.
- ripgrep's jemalloc runs autoconf's `configure`, which links a test program by the C compiler alone: for musl, clang found no crt objects, libc or libgcc. musl-dev keeps them in its Debian folder, `usr/lib/<triple>`, which clang doesn't search, and the sysroot had no crtbegin or libgcc: Rust brings its own for its links. The musl sysroots now take GCC 8's crtbegin and libgcc, the glibc sysroots' package, into that folder, and the wrapper points clang to it when linking, with libgcc static, as Debian's `musl-gcc` does.
- The test crate's build script links a C program by the C compiler, as `configure` does, for every target.
